Overview

A CPU, and only a CPU

SPK286 implements the Intel 80286 as RTL. The repository ends at the CPU boundary: execution core, microcode and its compiler, prefetch, segmentation and protection, interrupts, task switching, the Bus Interface Unit and the timing policy. Machine designs, whether on an FPGA platform or in custom hardware, consume it as a component.

µC

Project-owned microcode

Human-readable .mc source compiled by a deterministic Python tool into a synchronous ROM. Microcode requests functional operations; it is not a second x86 decoder.

PM

Full protected mode

Descriptors, privilege checks, call, interrupt, trap and task gates, task switching, IOPL, exception replacement, double fault and shutdown.

HW

Hardware-derived oracle

Checked against the SingleStepTests/80286 captures from a physical Harris N80C286-12, plus directed benches in two simulators and mutation audits.

How to read this datasheet

SPK286 is functionally complete for the documented 80286 and its two best-known undocumented instructions. It does not yet claim historical cycle accuracy: execution is dependency-driven, and the historical schedule is a provisional, separable layer.

02

Logical design

Core architecture

Every piece of state has one owner. Architectural registers, segment caches, protected-mode state, the stack and operand services and the BIU each own what they hold; microcode asks them for operations and waits for real dependencies.

Code fetches and every data, I/O, descriptor, TSS and interrupt acknowledge cycle are issued through the BIU. Data access never flushes the prefetch queue.

Instruction stream

  • One outstanding code fetch; the fetch cursor may run ahead of IP by the queue capacity plus one response.
  • Refill needs two free queue slots; bytes are queued low byte first.
  • A redirect flushes the queue and discards the response of any code read still in flight.
  • The instruction start CS:IP and TF are captured at opcode consumption and become the saved IP for faults.
  • Instruction length is qualified without side effects against the ten-byte limit.

Operands and stack

  • ModR/M and displacement are captured once; later queue bytes cannot alter the executing instruction.
  • Each byte or word access is checked against the cached limit and rights before any bus cycle.
  • 16-bit offsets wrap; physical addresses are 24 bits.
  • PUSH SP pushes the original SP; POP SP loads the popped value.
  • A faulting POP to memory keeps its SP increment, as observed on physical parts.

External interface

A normalized 80286 bus

The bus is a synchronous transaction interface, not a pin-accurate model. A native wrapper can translate it to 80286 pin polarities and the full S0/S1/M-IO/COD-INTA encoding.

Bus status encoding

0 · INTA 4 · halt / shutdown 5 · MEMR 6 · MEMW 9 · IOR A · IOW D · CODE F · passive
  • After reset CS=F000 with hidden base FF0000 and IP=FFF0, so the first fetch is at FFFFF0.
  • Address, status, BHE and write data hold while bus_valid && !ready.
  • An odd word is two ordered cycles (N on D15:8, then N+1 on D7:0), each waiting for its own READY, with bus ownership kept between them.
  • At a free boundary an accepted data request wins over code; once visible, a cycle keeps the bus until READY.
  • HOLD is granted only at a free boundary and never splits an odd word, a locked read-modify-write or the INTA chain.
  • Interrupt acknowledge is two READY-qualified INTA cycles; the vector is D7:0 of the second, and LOCK links both with the first stack push.
  • Halt and shutdown are indicated with status 4 and address 2 or 0, without a READY-qualified transfer.

Setup and debug ports

The top level also exposes setup ports (register, FLAGS, IP and segment writes plus a coordinated redirect) used by test harnesses, and read-only debug_* ports for registers, segment caches, protected-mode state, micro-PC, events, bus activity and timing counters.

04

Control store

Readable microcode, deterministic ROM

Source is authoritative

Instructions are written in microcode/source/*.mc as named functional operations. The compiler checks operands and temporary lifetimes, resolves entries and labels, and emits one ROM word per statement. Timing annotations, padding and arbitrary branches are rejected by the language. 

microcode_format 21

# Undocumented 80286 SALC: AL = CF ? FFh : 00h; preserve AH and all FLAGS.
instruction LOAD_CARRY_BYTE:
    READ_FLAGS -> TMP0
    CARRY_FILL8 TMP0
    TMP0 -> DST8
    END

µ

Execution contract

The decoder consumes the opcode and loads the generated entry with captured metadata. The microsequencer owns micro-PC and active state and knows nothing about x86. The executor completes an operation only when its real dependency is satisfied — a queue byte, an operand response, BIU completion — and otherwise the sequencer holds.

Reset and redirects clear microstate; pauses hold it. An invalid ROM address or word latches microcode_fault.

Reproducible artifacts

  • No timestamps or absolute paths in the output.
  • Generated files are committed and never edited by hand.
  • A stale artifact fails every build.
  • Frozen images of earlier formats keep extensions append-only.
  • Each micro-PC maps back to its source line.

Instruction set

The documented 80286, and then some

AreaStatusNotes
Real-mode instructions Complete Every documented form; all 307 opcode forms checked against hardware captures.
Protected mode Implemented System instructions, segment loads, gates, task switching, IOPL, #DF and shutdown.
LOADALL (0F 05) Implemented Fixed 102-byte image at 000800h, atomic commit, #GP(0) at nonzero CPL.

80386 behavior Excluded No granularity, 32-bit fields or operand-size prefixes, by design.

Real mode

  • Data transfer, byte and word ALU, TEST, INC/DEC/NEG/NOT.
  • Shifts and rotates, including immediate counts.
  • MUL/IMUL/DIV/IDIV and immediate IMUL; decimal and ASCII adjust.
  • String instructions with REP/REPE/REPNE, restartable per iteration and interruptible between iterations.
  • Port and string I/O, PUSHA/POPA, ENTER/LEAVE, BOUND.
  • Near and far transfers, LOOP/JCXZ, INT/INTO/IRET, HLT, segment override and LOCK prefixes.
  • Byte IDIV overflow follows the physical 80286 captures; invalid opcodes raise #UD.

Protected mode

  • LMSW, SMSW, LGDT, SGDT, LIDT, SIDT, LLDT, SLDT, LTR, STR, VERR, VERW, LAR, LSL, ARPL, CLTS — checks before any side effect.
  • Segment loads with selector, type, privilege, presence and limit checks, accessed-bit write-back and expand-down segments.
  • Far CALL/JMP/RET, conforming and non-conforming, through call gates with parameter copying and TSS stacks.
  • Interrupt and trap gates with error codes and outer-level stacks; same- and outer-level IRET.
  • Task switching through TSS descriptors and task gates, busy bits and NT back-link.
  • IOPL checks on CLI/STI/IN/OUT/INS/OUTS; POPF/IRET FLAGS privileges.

Interrupts and exceptions

Intel priority at every boundary

At an instruction boundary, instruction faults come first, then the TF single-step trap, then NMI, then INTR.

RequestVectorSaved IPNotes
Instruction fault0, 5, 6, 7, 10–13Instruction start, prefixes includedNever retires; #DF (8) on a fault during delivery.
Single step (TF)1Next / target IPTF is sampled at instruction start.
NMI2Next instructionOne pending edge; blocked until IRET.
INTRINTA vectorNext instructionNeeds IF=1 and no STI/SS shadow.
INT3 / INT n / INTO3 / n / 4Next instructionRetires when entry completes; INT clears TF without trapping.
  • Real-mode entry pushes FLAGS, CS and IP, clears IF and TF, reads the IVT, then commits CS:IP and flushes the queue in one step.
  • No event is admitted inside a frame or a physical operand word.
  • A frame push that cannot complete leads to double fault or shutdown, never to unbounded recursion.
  • STI creates a one-instruction shadow only when IF goes from 0 to 1; MOV SS and POP SS inhibit interrupts for one instruction.
07

Timing model

Function first, timing as a separate layer

The number of micro-operations an instruction uses does not define its historical cycle count, and no idle or padding micro-operations exist. Timing is applied by an explicit policy, and real dependencies are honored in every mode.

Baseline

timing_policy_request = 0. Normalized, dependency-driven functional execution.

Available

Max

timing_policy_request = 2. Dependency-driven, functionally identical to the baseline.

Available

Profiled variant

spk286_profiled holds retirement until an Intel-derived per-instruction budget expires, counted in host-supplied virtual CPU clocks.

Provisional

Observation without intrusion

spk286_timing_trace counts cycles, BIU busy time, READY waits, prefetch requests and responses, queue-empty cycles, redirects, operand waits and events. Unsupported policy requests fall back to 0 and set debug_timing_policy_error. The profiled variant is a generated drop-in copy of the top level; with historical_enable=0 it behaves as the functional core.

!
No cycle-accuracy claim

The long-term modes are Accurate (validated historical timing), Fast and Max. Native Ts/Tc bus timing, prefetch overlap and named 6–25 MHz profiles are not yet validated against hardware, and a profile is not called accurate because a nominal MHz or aggregate benchmark matches.

Python test modules

SingleStepTests/80286 as the functional oracle

The corpus was captured from a physical Harris N80C286-12 in real mode (pinned commit 37c73ca, MIT licence). Each MOO test is normalized, loaded into the RTL, run to one target retirement and compared on final registers and the whole sparse memory image, including neighbouring bytes. Undefined FLAGS bits are masked with the corpus masks. 

MOO test -> normalized state -> RTL initialization -> one target retirement
         -> final registers and sparse RAM -> masked comparison

Every admitted case runs, including prefixed and exception-terminated ones. The 307 documented real-mode forms account for 1,386,996 cases; the rest cover SALC and the no-NPX 9B/D8 captures. Three cases are revoked upstream, and one record without a captured write strobe is reported as not evaluable — never as a pass.

Directed benches

Each bench in sim/unit runs under both Verilator and Icarus Verilog. Many are driven by vectors from independent Python reference models in tools/, so the expected values do not come from the RTL under test.

Checking the checkers

Mutation audits inject isolated RTL faults into temporary copies and require the benches to reject each one. make verify-failure proves both simulators report a wrong expectation, and the MOO parser is cross-checked against the upstream reference parser.

Known limitations

What still needs evidence

Where Intel documentation, emulators and physical parts disagree or stay silent, SPK286 implements a documented policy and records the question as open instead of picking an answer quietly.

Functional

  • Explicit LOCK privilege rules and the protected zero-count INS/OUTS boundary.
  • LAR/LSL/VERR/VERW truth tables for absent and conforming descriptors.
  • NT after a JMP task switch keeps the incoming value; Intel table 8-2 and some emulators disagree.
  • The multi-word boundary and restart matrix is only partly covered.
  • Competing-event ordering needs a wider independent matrix.

Policies pending physical evidence

  • NMI blocking is released at IRET start, including a faulting IRET.
  • The STI shadow exists only on a 0-to-1 IF transition.
  • A faulting instruction does not also produce a single-step trap.
  • Event recognition order for zero-count REP instructions.
  • LOADALL stepping-specific details and images that clear PE.
!
Verification gap

No directed bench yet covers an owed TF, NMI or INTR event at an instruction boundary competing with a fetch fault of the next instruction. Real-mode fetch wraps at FFFF, so the case only arises at a protected-mode CS limit.

Scope and usage

Integrating the core

Inside SPK286

  • CPU top level, decoder, microsequencer and datapath.
  • Microcode source, compiler and generated ROM.
  • Prefetch, segmentation, protection and task switching.
  • Interrupts, exceptions and the BIU.
  • Timing policy and CPU-only verification.

Left to the machine

  • PIC, PIT, DMA, 8042, RTC/CMOS and ISA.
  • Video, audio and storage.
  • BIOS packaging and PC/AT memory map.
  • Board top levels, memory controllers and platform integration.

Instantiation

Instantiate spk286 from rtl/spk286.sv with the sources listed in scripts/rtl_sources.sh: the generated microcode package and ROMs first, then rtl/*.sv. rtl/timed/spk286_profiled.sv is a drop-in variant that adds the optional historical instruction-interval schedule.

Requirements: Verilator 5.020 or later, Icarus Verilog 12, Yosys, GNU make and Python 3 with the standard library only. On Ubuntu or WSL, make bootstrap installs them and make env checks them. 

make regression        # microcode, lint, directed benches, Python tests, synthesis
make singlestep-fetch  # fetch the pinned SingleStepTests/80286 corpus
make singlestep        # run every supported SingleStep opcode file
make mutation-audit    # check that the benches reject injected RTL faults
make full-check        # everything, plus the profiled variant checks
