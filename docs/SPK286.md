# SPK286 technical reference

SPK286 is a synthesizable SystemVerilog implementation of an Intel
80286-compatible CPU core. This document describes its scope, architecture,
external interface, microcode, implemented instruction set, timing model and
verification. It is the single technical reference for the repository.

## 1. Scope and design rules

SPK286 ends at the CPU boundary. It contains:

- the CPU top level, decoder, microsequencer and execution datapath;
- register, FLAGS, segment-cache and protected-mode state;
- the project-owned microcode source, compiler and generated ROM;
- the prefetch unit, effective-address logic, segmentation and protection;
- interrupts, exceptions and task switching;
- the Bus Interface Unit (BIU) and a normalized 80286-style bus;
- READY, HOLD/HLDA, LOCK, INTR/NMI and INTA behavior;
- the timing policy and a profiled timing variant;
- CPU-only verification, debug and synthesis infrastructure.

Machine logic (PIC, PIT, DMA, 8042, RTC/CMOS, ISA, video, storage, BIOS
mapping, FPGA board top levels) is out of scope. Machine designs, whether on
an FPGA platform or in custom hardware, consume SPK286 as a CPU component.

The following rules shape the implementation:

- **Functional semantics and timing are separate.** The number of
  micro-operations an instruction uses does not define its historical cycle
  count. No idle or padding micro-operations exist. Timing is applied by an
  explicit policy layer (section 8).
- **Real dependencies are always honored**: READY, BIU completion, instruction
  byte availability, operand availability, bus ownership, queue flush/redirect
  completion and required serialization, in every timing mode.
- **One owner per state.** Architectural registers, segment caches,
  protected-mode state, the stack arithmetic service, the operand service and
  the BIU each own their state. Microcode requests operations from these
  owners; it is not a second x86 decoder and does not sequence bus cycles.
- **80286 behavior only.** No 80386 architectural behavior (granularity,
  32-bit fields, operand-size prefixes) is introduced. Expected behavior
  derives from Intel 80286 documentation and physical 80286 evidence;
  emulators are reference material, not authority.
- **Generated microcode is committed** and reproducible; stale artifacts fail
  the build.

## 2. Architecture

                    |
                    v
          six-byte prefetch queue
                    |
                    v
   instruction context / prefixes -> decoder -> microsequencer -> ROM
                                                  |
                                                  v
                                           micro-executor
              +-------------+-------------+-------+------+--------------+
              |             |             |              |              |

### 2.2 Instruction stream and retirement

- `fetch` keeps one transaction in flight. Its cursor advances when data
  arrives; architectural IP advances only when the frontend consumes a byte.
  The fetch cursor may run ahead of IP by the queue capacity plus one
  response.
- Queue bytes are ordered low byte first for each fetch response. Refill needs
  at least two free slots.
- A redirect (control transfer, event entry or LOADALL commit) flushes the
  queue; any outstanding code read completes and its response is discarded
  before the new stream starts.
- Opcode consumption captures the instruction start CS:IP and TF. That
  context survives all ModR/M, displacement and immediate reads and is the
  saved IP for faults.
- `instruction_retired` is a one-clock pulse after END. A faulting
  instruction never retires; software INT retires when its entry completes.
  `event_completed` independently marks every completed delivery.
- Real-mode instruction fetch wraps IP at FFFF; in protected mode a fetch
  beyond the CS limit faults.
- `execute_enable=0` pauses semantic execution. Accepted bus cycles may finish
  and their responses are held until execution resumes; nothing is repeated.

### 2.3 Operands, stack and data access

- ModR/M and displacement bytes are acquired once and captured; later queue
  bytes cannot alter the executing instruction. BX+SI, BX+DI, SI, DI and BX
  default to DS; BP-based forms default to SS. Offsets wrap at 16 bits;
  physical addresses are 24 bits.
- A whole byte/word access is checked against the cached segment limit and
  access rights before any bus cycle. A word at offset FFFF is never split
  across a wrapped offset.
- PUSH sources are captured before SP changes. POP commits SP+2 before writing
  its destination, so POP SP loads the popped value and a faulting POP to
  memory keeps the SP increment (as observed on physical 80286 parts).
- The executor owns temporaries TMP0 (original destination), TMP1 (source)
  and TMP2 (result), candidate FLAGS and a pending FLAGS mask. FLAGS commit
  follows the complete logical write.
- Undefined FLAGS bits follow an explicit, documented policy per instruction
  family and are masked in hardware comparisons.

## 3. External interface and BIU

The bus is a normalized transaction interface, not a pin-accurate model of
the 80286. A native wrapper may translate it to pin polarities and the full
S0/S1/M-IO/COD-INTA encoding; its planned contract is in
[NATIVE_BUS.md](NATIVE_BUS.md).

| Signal | Dir | Meaning |
| --- | --- | --- |
| `clk` | in | Synchronous core clock. |
| `reset` | in | Active-high synchronous reset; inhibits bus output while asserted. |
| `ready` | in | Completes the active bus cycle. |
| `address[23:0]` | out | Physical address. |
| `data_in[15:0]` | in | Read data, sampled on the READY edge of an active read. |
| `data_out[15:0]`, `data_oe` | out | Write data on the selected lanes and its drive enable. |
| `bus_valid`, `bus_write` | out | Active cycle and direction. |
| `bus_bhe_n` | out | Active-low upper byte enable. |
| `bus_status[3:0]` | out | `0` INTA, `4` halt/shutdown indication, `5` MEMR, `6` MEMW, `9` IOR, `A` IOW, `D` CODE, `F` passive. |
| `bus_lock` | out | LOCK for explicit LOCK, implicit XCHG, and the INTA/first-push chain. |
| `intr`, `nmi` | in | INTR is level sensitive; NMI is a rising edge. Synchronous to `clk`. |
| `hold_request`, `hlda` | in/out | HOLD request and grant at a free cycle boundary. |
| `execute_enable` | in | Pauses or resumes semantic execution. |
| `timing_policy_request[1:0]` | in | Timing policy sampled at reset (section 8). |
| `halted`, `shutdown` | out | HLT and shutdown states. |

The top level also exposes setup ports (register, FLAGS, IP and segment
writes plus a coordinated `redirect`) used by test harnesses to initialize
state, and read-only `debug_*` ports for registers, segment caches,
protected-mode state, microcode PC, events, bus activity and timing counters.

Bus behavior:

- After reset CS=F000, hidden CS base=FF0000, IP=FFF0; the first fetch is at
  FFFFF0.
- Address, status, BHE and write data hold while `bus_valid && !ready`.
  Responses are retained until their consumer accepts them.
- Code fetch: an even word uses both lanes; an odd address returns one byte
  on D15:8; the next request is word aligned. Fetch never crosses the cached
  CS limit.
- Data: an odd word is two ordered cycles (A=N on D15:8, then A=N+1 on D7:0),
  each waiting for its own READY, with ownership retained between them. Port
  addresses are zero-extended from 16 bits.
- Arbitration: at a free boundary an accepted data request wins over code;
  once a cycle is visible its owner keeps the bus until READY. Data access
  never flushes the prefetch queue.
- HOLD is granted only at a free boundary; it never splits an odd word, a
  locked read-modify-write or the INTA chain.
- Interrupt acknowledge uses two READY-qualified INTA cycles (status 0,
  address 0); the vector is D7:0 of the second. LOCK links both INTA cycles
  and the first stack push.
- Halt and shutdown are indicated with status 4 and address 2 or 0 without a
  READY-qualified transfer.
- Reset aborts an active cycle. Cancellation drains accepted transfers and
  discards their responses; external side effects cannot be undone.
- `debug_bus_transaction` labels protected-mode activity (descriptor, TSS,
  gate, frame/stack, protected fetch) for diagnostics only.

## 4. Architectural and protected-mode state

- Segment registers have a visible selector and a hidden cache (24-bit base,
  16-bit limit, 8-bit access). Real-mode loads set base = selector x 16,
  limit FFFF and access 93h (present, writable, accessed data).
- `spk286_protected_state` is the single commit owner for MSW, CPL, GDTR,
  IDTR, LDTR and TR (selector plus hidden base/limit/access). Descriptor,
  task and LOADALL services request commits through it.
- With PE set, the selected protected cache supplies base, limit and access
  for every logical access. Expand-down data and stack segments are
  supported.
- LOADALL, task switches and descriptor loads stage their complete result and
  commit it atomically on one clock edge.

## 5. Microcode

### 5.1 Source language

The authoritative source is `microcode/source/*.mc`. Files are compiled in
sorted path order; entries keep source order. Each file starts with
`microcode_format N`; the format version gates which operations are accepted.

```text
microcode_format 21

# Undocumented 80286 SALC: AL = CF ? FFh : 00h; preserve AH and all FLAGS.
instruction LOAD_CARRY_BYTE:
    READ_FLAGS -> TMP0
    CARRY_FILL8 TMP0
    TMP0 -> DST8
    END
```

- `instruction NAME:` starts an entry (uppercase snake case); lowercase labels
  are debug symbols scoped as `ENTRY.label`.
- Statements name functional operations (`DECODE_MODRM`, `READ_RM16 -> TMP0`,
  `ALU DECODED TMP0, TMP1 -> TMP2 FLAGS_DECODED`, `COMMIT_FLAGS`,
  `TASK_SWITCH`, `LOADALL`, ...). Every path ends in `END`.
- Temporaries must be defined before use. Timing annotations, padding and
  arbitrary branches are rejected; the only branches are bounded functional
  ones defined by specific operations.
- Comments start with `#` and are not semantic.

### 5.2 Compiler and artifacts

`tools/microcode/compile_microcode.py` (Python standard library only) parses,
validates operands and temporary lifetimes, resolves entries and labels, and
encodes one ROM word per statement. Output is deterministic: no timestamps or
absolute paths. The current image has 123 entries in 743 words with 10-bit
addresses and 8-bit control.

| File in `microcode/generated/` | Content |
| --- | --- |
| `spk286_microcode_pkg.sv` | Dimensions, operation constants and entry constants. |
| `spk286_microcode_rom.sv` | Portable combinational ROM with validity output. |
| `spk286_microcode_sync_rom.sv` | Synchronous ROM inferred as block memory; used by the core. |
| `spk286_microcode.lst` | Symbolic listing with source locations. |
| `spk286_microcode_symbols.json` | Entries, labels and per-PC source mapping. |
| `spk286_microcode_validation.json` | Format/encoding versions, source hashes, usage and status. |

```text
make microcode          # regenerate
make microcode-check    # fail if any artifact is stale (run by every build)
make microcode-test     # compiler and frozen-format tests
make microcode-audit    # independent ROM reconstruction and round-trip
python3 -m tools.microcode.compile_microcode --lookup MOV_R16_IMM16.writeback
python3 -m tools.microcode.compile_microcode --pc 0x1
```

Earlier ROM formats remain compilable; tests in `tests/test_microcode*.py`
compare their frozen images (`tests/fixtures/microcode_*.json`) so that
extensions are append-only and never relocate existing entries silently.

### 5.3 Execution contract

The decoder consumes the opcode and loads the generated entry with captured
metadata. The microsequencer owns micro-PC, entry and active state and knows
nothing about x86. The executor completes each operation only when its real
dependency is satisfied (queue byte, operand response, BIU completion);
otherwise the sequencer holds. Reset and redirects clear microstate; pauses
hold it. An invalid ROM address or word latches `microcode_fault`.

## 6. Instruction set coverage

### 6.1 Real mode

Every documented 80286 real-mode instruction is implemented: data transfer,
byte and word ALU, TEST, INC/DEC/NEG/NOT, shifts and rotates (including
immediate counts), MUL/IMUL/DIV/IDIV and immediate IMUL, decimal and ASCII
adjust, string instructions with REP/REPE/REPNE, port I/O and string I/O,
stack operations, PUSHA/POPA, ENTER/LEAVE, BOUND, near and far control
transfers, LOOP/JCXZ, INT/INTO/IRET, flag instructions, HLT, segment override
and LOCK prefixes. Invalid opcodes raise #UD (6).

Selected behaviors:

- String instructions are restartable per iteration and recognize
  interrupts between iterations.
- Byte IDIV overflow follows the physical 80286 behavior captured in the
  SingleStep corpus.
- A POP to memory whose destination faults keeps its SP increment.
- PUSH SP pushes the original SP (80286 behavior).

### 6.2 Protected mode

- System instructions: LMSW, SMSW, LGDT, SGDT, LIDT, SIDT, LLDT, SLDT, LTR,
  STR, VERR, VERW, LAR, LSL, ARPL, CLTS, with mode and privilege checks
  performed before any side effect.
- Segment loads with full selector, type, privilege, presence and limit
  checks, accessed-bit write-back and atomic cache commit; null selectors for
  DS/ES.
- Far CALL/JMP/RET to code segments, conforming and non-conforming, and
  through call gates (same-level and inter-level with parameter copying and
  TSS-selected stacks); inter-level RETF with outer stack validation.
- Interrupt and trap gates with error-code frames, outer-level event stacks,
  same- and outer-level IRET.
- Task switching through TSS descriptors and task gates (CALL, JMP, INT,
  exceptions, nested IRET) with busy bits, NT/back-link handling, incoming
  LDTR and segment validation and late exception context.
- CLI/STI/IN/OUT/INS/OUTS IOPL checks; POPF/IRET FLAGS privileges.
- Exception replacement, double fault (#DF) and shutdown.
- No coprocessor is attached. ESC raises #NM (7) when MSW.EM or MSW.TS is
  set; otherwise it validates its first memory operand word and completes
  without an NPX transfer. WAIT raises #NM when MSW.MP and MSW.TS are both
  set and otherwise completes (BUSY is inactive).

### 6.3 Undocumented and compatibility instructions

- **LOADALL (`0F 05`)** reads the fixed 102-byte image at physical 000800h
  as 51 words and commits GPRs, IP, FLAGS, MSW, system registers, selectors
  and all hidden caches atomically. It raises #GP(0) at nonzero CPL and
  rejects an image that clears PE while in protected mode. `0F 04` and other
  `0F` holes remain invalid.

  | Offset | Size | Field |
  | ---: | ---: | --- |
  | 00 | 6 | Reserved |
  | 06 | 2 | MSW |
  | 08 | 8 | Reserved |
  | 10 | 2 | TR selector |
  | 12 | 2 | FLAGS |
  | 14 | 2 | IP |
  | 16 | 2 | LDT selector |
  | 18 / 1A / 1C / 1E | 2 each | DS / SS / CS / ES selectors |
  | 20 | 16 | DI, SI, BP, SP, BX, DX, CX, AX |
  | 30 / 36 / 3C / 42 | 6 each | ES / CS / SS / DS hidden caches |
  | 48 | 6 | GDTR (base low, base high, limit) |
  | 4E | 6 | LDT hidden cache |
  | 54 | 6 | IDTR |
  | 5A | 6 | TSS hidden cache |

  Each hidden cache record is base low word, base high byte, access byte and
  limit word.
- **SALC (`D6`)**: `AL = CF ? FFh : 00h`; AH and all FLAGS are preserved.

## 7. Interrupts and exceptions

Priority at an instruction boundary follows Intel: instruction faults, then
the TF single-step trap, then NMI, then INTR.

| Request | Vector | Saved IP | Notes |
| --- | --- | --- | --- |
| Instruction fault | 0, 5, 6, 7, 10-13 | Instruction start (including prefixes) | Never retires; #DF (8) on a fault during delivery. |
| Single step (TF) | 1 | Next/target IP | TF is sampled at instruction start. |
| NMI | 2 | Next instruction | One pending edge; blocked until IRET. |
| INTR | INTA vector | Next instruction | Needs IF=1 and no STI/SS shadow. |
| INT3 / INT n / INTO | 3 / n / 4 | Next instruction | Retires when entry completes; INT clears TF without trapping. |

- Real-mode entry pushes FLAGS, CS and IP, clears IF and TF, reads the IVT
  offset and selector, then commits CS:IP and flushes the queue in one step.
  Protected-mode entry adds gate, privilege and stack-switch processing and an
  error code where required.
- No event is admitted inside a frame or a physical operand word. A frame push
  that cannot complete leads to double fault or shutdown, never to unbounded
  recursion.
- STI creates a one-instruction shadow only when IF changes from 0 to 1;
  POPF and IRET do not create it. MOV SS and POP SS inhibit interrupts for one
  instruction.
- Reset clears pending NMI, NMI blocking, shadows, halt and shutdown.

## 8. Timing model

Functional execution is dependency-driven and does not claim historical cycle
accuracy. Timing is layered on top:

- **Timing policy** (`timing_policy_request`, sampled only at reset):
  `0` normalized functional baseline, `2` Max (dependency-driven, functionally
  identical). Unsupported requests fall back to 0 and set
  `debug_timing_policy_error`.
- **Timing trace** (`spk286_timing_trace`): non-intrusive counters for cycles,
  BIU busy time, READY waits, prefetch requests and responses, queue empty
  cycles, redirects, operand waits and events.
- **Profiled variant** (`rtl/timed/spk286_profiled.sv`): a generated copy of
  the top level that adds `historical_enable`, `cpu_boundary` and
  `timing_read_wait_event`. With `historical_enable=1`, an instruction
  interval scheduler (`rtl/timing`) holds retirement until an Intel-derived
  per-instruction budget expires, counted in host-supplied virtual CPU
  clocks. Functional services still run at fabric speed and every real
  dependency still applies. With `historical_enable=0` it behaves as the
  functional core. It is generated by `make profiled` and checked by
  `make profiled-check`.

The conceptual long-term modes are **Accurate** (validated historical
timing), **Fast** (reduced instruction delays with a compatibility BIU) and
**Max** (dependency-driven). Only the baseline and Max policies and the
provisional interval model exist today. A profile is not called accurate
because a nominal MHz or aggregate benchmark matches; native Ts/Tc pin timing
and prefetch overlap are not validated.

### 9.3 Directed testbenches

`sim/unit/*_tb.sv` hold the directed testbenches, listed in
`scripts/test_units.sh`. Each runs in both simulators (the long expand-down
matrix runs in Icarus only). Many are driven by vectors produced by
independent Python reference models in `tools/*_reference.py` and
`tools/*_vectors.py`, so the expected values do not come from the RTL. Run one
bench with `bash scripts/test_units.sh both spk286_alu`.

### 9.4 SingleStepTests/80286

The hardware-derived corpus (Harris N80C286-12, real mode, commit
`37c73caf53dcd22d3dd369ff09305d13d117a4fe`, MIT license) is the main
functional oracle:

```text
MOO test -> normalized state -> RTL initialization -> one target retirement
         -> final registers and sparse RAM -> masked comparison
```

- `tools/singlestep.py` reads MOO 1.1 directly (including gzip) and applies
  the upstream revocation list. `tools/run_singlestep.py` prepares and runs
  cases on the Verilator executable; `tools/run_singlestep_all.py` runs every
  supported file.
- Each test ends with `HLT`; SPK286 stops at the target instruction's
  retirement and compares the published final IP minus one.
- Undefined FLAGS bits are masked with the corpus masks. The full sparse
  memory image is compared, including neighbouring bytes.
- Every admitted case runs, including prefixed and exception-terminated
  cases. All 310 supported opcode files run: 1,397,996 cases pass with zero
  failures (3 cases are revoked upstream). The 307 documented real-mode forms
  account for 1,386,996 of them; the rest cover SALC (`D6`) and the no-NPX
  `9B`/`D8` captures.
- One record (`E7.MOO.gz`, index 1100) lacks a captured write strobe in the
  corpus. `tools/singlestep_admission.py` recognizes exactly that record by
  index, hash and file hash and reports it as not evaluable; it is never
  counted as a pass and no other record can be admitted this way.

### 9.5 Other checks

- Mutation audits (`tools/audit_*.py`) cover operand boundaries, ALU, stack

  HOLD/LOCK and ESC, double fault, null LDTR and task publication.
  `tests/test_mutation_anchors.py` keeps every mutation anchor unique in the

- `make verify-failure` proves that both simulators report a wrong

- `make synth-check` runs Yosys over each module and the whole core.
- `make timing-trace` and `make timing-calibration` capture timing
  observation traces and the instruction calibration suite.
- `make resource-report` estimates Cyclone V resources with Yosys

## 10. Known limitations and open items

Functional:

- Explicit LOCK privilege rules and the protected zero-count INS/OUTS
  privilege boundary need independent 80286 evidence.
- LAR/LSL/VERR/VERW truth tables for absent and conforming descriptors need a
  physical 80286 discriminator (the LSL conforming-code case differs between
  sources).
- The NT flag after a JMP task switch preserves the incoming value; Intel
  table 8-2 and some emulators disagree, pending a physical observation.
- The multi-word boundary and restart matrix (LES/LDS, BOUND, ENTER, PUSHA,
  POPA, far pointers, REP, parameter copying, system-table operands at limit,
  FFFF and 24-bit wrap) is only partly covered.
- Competing-event ordering (SS shadows, STI, faults, TF, NMI, INTR, REP,
  failed IRET) needs a wider independent matrix.

Verification gap:

- No directed bench covers an owed TF/NMI/INTR event at an instruction
  boundary competing with a fetch fault of the next instruction. Real-mode
  fetch wraps at FFFF, so the case only arises at a protected-mode CS limit.

Behaviors implemented as documented policies pending physical evidence:

- NMI blocking is released at IRET start, including a faulting IRET.
- The STI shadow is created only on a 0-to-1 IF transition.
- A faulting instruction does not also produce a single-step trap.
- Event recognition order for zero-count REP instructions.
- LOADALL: stepping-specific details, reserved FLAGS and protected images
  that clear PE.

Timing:

- No historical cycle accuracy is claimed. Native Ts/Tc/idle bus timing,
  prefetch overlap and named historical profiles (6-25 MHz) remain to be
  validated against physical hardware.
